## What's Working

1. **Keycap button affordance.** The `border-bottom: 3px solid var(--accent-edge)` + `translateY(2px); border-bottom-width: 1px` on `:active` is physically legible at arm's length on a touch kiosk. It communicates pressability without hover.

2. **Cancel-and-restore path.** `cancelBuild()` → `/api/reset` → `retryLastBuild()` routing back to `lastComposeScreen` with words intact is production-quality. The `setStep()` replay guard (state-change gate) eliminates the CSS animation restart bug; the 2-render vs 22-render proof is real.

3. **Two-voice typography is implemented with discipline.** Archivo carries every user-facing heading and instruction; IBM Plex Mono carries every step message, spec value, and timing. The `.step-name` (Archivo) / `.step-msg` (mono) pairing on the build log is the clearest expression of the rule.

## Priority Issues

**[P0] "Start over" has three destinations across three screens**
- View screen (line 1768): `onclick="goToSpeak()"` — clears speak prompt, navigates to speak. Engineer-mode users land in the wrong mode.
- Slicing screen (line 1821): `onclick="startOver()"` — resets all state, navigates to idle.
- Error screen (line 1839): `onclick="startOver()"` — same as slicing.
- Why it matters: A user who generated an engineer part, saw it render, then tapped "Start over" is in speak mode with an empty textarea. They cannot find their way back to engineer mode without discovering the mode panels on the home screen. For a first-timer, this is disorienting.
- Fix: Unify all three to `startOver()` (idle reset) OR rename the view-screen button to "New object" / "Try again" and route it through `goHome()`. The label must match the destination.
- Suggested command: /impeccable harden

**[P1] Raw JS error messages reach walk-up users**
- Lines 2709, 2723, 2787: `showError('...: ' + e.message)` — a walk-up sees "Could not load model: Failed to fetch" or "Could not reach server: NetworkError when attempting to fetch resource."
- Line 2638: `escapeHtml(e.message)` injected into library card DOM.
- Line 2502: `e.message.slice(0, 20)` truncated into button text.
- Why it matters: These are developer-facing strings on a public kiosk. A stranger gets no actionable information and loses trust.
- Fix: Introduce `friendlyError(e)` mapping network errors → "The kiosk lost its connection. Please try again or ask for help."; HTTP 5xx → "Something went wrong on our end. Press Try Again or ask a staff member."; fallback → "An unexpected error occurred." Replace all five raw-message sites.
- Suggested command: /impeccable harden

**[P1] Engineer pipeline step names are internal brand vocabulary**
- 8 steps: "Kite AI — agent auth", "You.com — web research", "Tavily — deep research", "Nebius — CAD generation", "Moonraker — dispatch", "Nebius — structural review" — none of these mean anything to a walk-up stranger.
- Why it matters: H2 (Match System/Real World). A kiosk user sees a developer's automation log, not a product working on their behalf. The brand names shift the frame from "this machine is making your part" to "this is a bunch of APIs doing stuff."
- Fix: Replace `.step-name` content with user-facing descriptions. Keep brand names as the `.step-msg` (mono subtext) for operator diagnostics. Example: step-name "Connecting AI" / step-msg (mono) "kite-ai · auth"; step-name "Researching specifications" / step-msg "you.com · web search". The two-voice rule makes this natural: Archivo names the step for the human; mono names the tool for the operator.
- Suggested command: /impeccable clarify

**[P2] Silent 90s idle timeout**
- `onIdle()` fires after 90s with no warning. Correctly skips generating/slicing/view screens. But will fire on speak and engineer mode, teleporting a typing user to idle.
- Fix: At T-15s, inject a dismissable toast: "Still here? Tap anywhere to continue — returning to home in 15 seconds." Any `touchstart` or `mousedown` (already wired to `resetIdle`) dismisses it automatically. Only call `onIdle()` if the toast was not dismissed.
- Suggested command: /impeccable harden

**[P2] "Saving to cloud" contradicts the kiosk's offline-resilient design**
- Step g-step-4 (`#g-step-4`) label reads "Saving to cloud." The kiosk self-hosts all fonts/vendors and saves to a SQLite gallery. "Cloud" triggers a mental model of external dependency that breaks down when the step fails or the kiosk is offline.
- Fix: Change label to "Saving to library" — matches the `nav-library-btn` vocabulary and accurately describes the SQLite gallery behavior.
- Suggested command: /impeccable clarify

## Persona Red Flags

**Jordan (walk-up first-timer):**
- "Start over" from the 3D viewer drops Jordan into speak mode, not idle. If Jordan arrived through engineer mode, they are now in the wrong panel with no visible "back to engineer" path.
- 90s idle timeout fires silently mid-inspection. Jordan spending 90 seconds reading the model will be teleported to idle.
- Tap-to-latch is not discoverable: the affordance label ("Hold the mic to speak — or tap it to talk hands-free") is 13px sage text — the smallest, dimmest text on the compose screen.

**Sam (motor accessibility / tremor):**
- Tap-to-latch is implemented. The 350ms threshold is reasonable.
- The `title=` attributes on every interactive element (25+ occurrences) are invisible on touch. Sam gets zero tooltip assistance.
- Aside tip cards are `display: none` at ≤900px — a narrow kiosk configuration loses all contextual help for a user who needs it most.

**Riley (engineer-mode spec-driven user):**
- "Start over" from the 3D view of an engineered part goes to speak mode, not engineer mode. Riley loses their spec text.
- 8 pipeline step names expose internal brand names ("Nebius — structural review"). Riley may reasonably wonder whether this is an error.
- The SCAD viewer auto-expands on the generating screen. Riley may value this; walk-up strangers do not. A disclosure toggle would serve both.

## Minor Observations

1. `copyStlToUsb()` at lines 2482–2512 references `document.getElementById('btn-stl')` which does not exist in the current HTML. Dead code from an older flow — safe to remove.

2. 25+ `title=` attributes on kiosk interactive elements are hover-only affordances that will never show on touch. They serve no user function and create dead maintenance surface.

3. `.panel-tag` copy ("MAKE · say it or type it", "ENGINEER · built to measure") uses `font-family: var(--font-mono)`. Per the two-voice rule, the human-directed subtext should be Archivo, or the tags should be shortened to mode designators only.

4. Boot restore: when `/api/state` returns `status: 'model_ready'`, a new walk-up sees a rotating object from the previous session with no "previous session" header. The view screen is excluded from idle reset so this state persists indefinitely.

5. `console.log('Library: loaded ' + models.length + ' models')` at line ~2595 is a debug statement in production code.

## Questions to Consider

- If "Saving to cloud" fails mid-engineer pipeline, does the UX communicate that the 3D model was successfully generated but only the save failed — or does the whole pipeline look like it failed? A user who waited 2+ minutes for their part to be engineered should not see a generic error and have to start from scratch.

- The SCAD viewer auto-expands on the engineer-generating screen. Who is this for? If it is for the operator watching over someone's shoulder, should it be behind a disclosure toggle ("Show technical output") rather than front-and-center for the walk-up user?

- `speak()` is defined and called 8 times but appears to be a no-op. Is TTS intended to ship eventually? If not, the function and its 8 call sites are dead-letter intent that will surprise the next developer who reads the file.
